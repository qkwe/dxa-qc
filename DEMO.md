# Демонстрационный сценарий (ТЗ п. 7.2)

Около 7 минут. Подготовка: `./run.sh build`, затем `TRAIN_DATA=/path/to/НД_для_обучения ./run.sh api`
(без `TRAIN_DATA` работает всё, кроме кнопки дообучения), открыть http://localhost:8000.
Входные данные — исходные DICOM: zip-архив или каталог (например, тестовый фрагмент организатора и
несколько исследований обучающего набора). Не загружайте `series.zip` — это результат сервиса, а не снимки.

## 1. Пакетная обработка (1 мин)
1. «Выбрать файлы» → zip (или «Папка...») → «▶ Обработать». Виден процент загрузки, затем «исследование i из n».
2. Сказать: сервис сам группирует снимки по исследованиям, определяет область и сторону, копии снимка
   обрабатывает один раз; на исследование — доли секунды на обычном CPU, без GPU и сети.
3. «Отчёт XLSX» — таблица в формате ТЗ 2.5 + `quality_prob` (Разъяснения V2): одна строка на снимок.

## 2. Как система принимает решение (2 мин)
1. Строка позвоночника с нарушением → справа снимок с разметкой и заключение числами:
   * ось — линия через центры крайних позвонков (кружки) против вертикали, «наклон 7.5° при допуске ТЗ 5°»;
   * зона гребней подвздошных костей внизу — зелёная/красная рамка (укладка);
   * галочка «посторонние предметы» — оранжевые рамки там, где сработал детектор.
2. Строка бедра: окружность головки, ось диафиза и офсет головки, жёлтый медиальный контур — по нему
   оценивается ротация (галочка «наибольший выступ контура»), зона седалищной кости, рамка области
   интереса с линией нижнего края малого вертела. На коротком скане рамка не строится — причина в легенде.
3. «🔍 Просмотр» — полный размер. В заключении у каждого критерия: измеренное значение, порог, вероятность.

## 3. Метрики (1 мин) — «таблицей с доверительными интервалами»
Кнопка «Метрики»: по каждому критерию ROC-AUC и F1 с 95% ДИ (вложенная CV по пациентам), режимы
чувствительности, поверка измерителя (угол — ошибка 0.19° при допуске 3°), стенд предметов на кости.
Сказать: всё это воспроизводится одной командой `./run.sh check` — без нас.

## 4. Предметы на кости (1 мин)
Показать на странице «Метрики» стенд: настоящие предметы перенесены на нормальные снимки; поверх таза
находится 96% (было 8%), поверх позвоночника 16% — честно: пластинки позвонков похожи на тонкий металл.

## 5. Гибкость и внедрение (1 мин)
* «⚙ Настройки...»: режим «высокая чувствительность» / «баланс» / «высокая специфичность» с честными цифрами,
  пороги ТЗ (изменение помечается в заключении «изменено пользователем; ТЗ: 5°»), отключение критериев.
* «■ Остановить» — прервать загрузку или обработку, обработанное сохраняется.
* Доп. серии для PACS: «Разметка и заключения (ZIP)» — PNG, DICOM SC, DICOM SR.

## 6. Врач в контуре (1 мин) — ТЗ 2.6 «с подтверждением специалистом»
1. Строка → «✎ Разметка врача»: врач подтверждает или исправляет заключение по каждому критерию,
   найденные сервисом предметы уже обведены пунктиром (ложную рамку — щелчком убрать), «Обвести предмет» —
   рамка мышью только на пропущенном; «Сохранить разметку».
2. «⟳ Дообучить и пересчитать метрики» (~5 мин — запустить заранее или показать готовый результат):
   сравнение действующей модели и кандидата по тем же честным метрикам; «Применить» / «Откатить».
   Сказать: новая модель только кандидат — одна ошибочная пометка не испортит сервис.

## Если что-то пошло не так
* Нет связи с интерфейсом — обработка из командной строки: `./run.sh predict <вход> <выход>`.
* Порт 8000 занят — `PORT=8080 ./run.sh api`.
