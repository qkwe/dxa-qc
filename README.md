# DXA-QC — контроль качества денситометрии (DXA)

Локальный сервис, который по DICOM-исследованию денситометрии поясничного отдела позвоночника
и проксимального отдела бедра определяет, качественное ли изображение, и если нет — какое
нарушение из утверждённого списка обнаружено, и объясняет почему (число, порог, картинка).

Подробный отчёт о том, что сделано, как и почему, — [REPORT.md](REPORT.md); демонстрационный сценарий — [DEMO.md](DEMO.md).

## Возможности

| Область | Нарушение (метка организатора) | Метод | AUC (честная CV) |
|---|---|---|---|
| Позвоночник | Не выравнена ось позвоночника | правило ТЗ: наклон > 5° | 0.85 |
| Позвоночник | Некорректная укладка | правило ТЗ: не видны гребни подвздошных костей | 0.90 |
| Позвоночник | Присутствуют посторонние предметы | детектор тонких ярких линий: мягкие ткани, поверх таза, поверх позвоночника (свой порог у каждой зоны) | 0.96 |
| Бедро | Некорректная укладка | ротация (малый вертел + офсет головки) и видимость седалищной кости | 0.86 |
| Бедро | Некорректная область интереса | правила ТЗ: < 3 см ниже малого вертела или скан короче 13 см | 0.90 |
| Всё | Качественное / есть нарушение | ИЛИ по критериям; `quality_prob` — AUC 0.86 | 0.83 |

* пакетная обработка каталога или zip (в т. ч. вложенного), группировка по `StudyInstanceUID`;
* таблица результатов `.xlsx` + `.csv` в формате ТЗ п. 2.5, одна строка на файл изображения;
* дополнительные серии: PNG и DICOM Secondary Capture с разметкой, DICOM SR с текстом заключения;
* HTTP API и веб-интерфейс для загрузки (файлы, zip или целая папка), просмотра и пакетной обработки;
* **настройки контроля** без переобучения: режим чувствительности, пороги, отключение критериев,
  размер пикселя, правило области — файлом, в API на каждое задание и в веб-интерфейсе (см. «Настройки»);
* ни одно исключение не прерывает пакет: ошибка файла → `processing_status = Failure` и текст в `error`;
  обработку и загрузку можно остановить («■ Остановить»), уже обработанное сохраняется;
* **инструмент врача** (`/review`): подтверждение или исправление заключения по каждому критерию,
  обведение пропущенного предмета, дообучение с честным пересчётом метрик, применение и откат модели;
* **проверка для организаторов** одной командой (`./run.sh check`) и страница «Метрики» (`/metrics`).

## Ограничения

* Обучено и проверено на 100 исследованиях одного аппарата (GE Lunar Prodigy Advance), 252 снимка.
  Пороги в градусах и сантиметрах аппаратно-независимы, но обучаемые пороги (детектор предметов,
  оценка ротации) и правило области по ширине снимка на другом аппарате могут потребовать перенастройки.
* Нарушений мало (6–36 на критерий), доверительные интервалы широкие — см. REPORT.md.
* Рамка области интереса GE в выгрузке не нарисована; область интереса бедра строится
  по анатомическим ориентирам, решение принимается по отступу снизу (см. REPORT.md, раздел 4.4).
  На коротком скане (поле < 13 см) ориентиры ненадёжны: рамка на оверлее не рисуется, решение —
  только по длине скана.
* Тег `(0040,0303) Exposed Area` в части файлов неверен; размер пикселя принимается только
  в диапазоне 0.1–1.5 мм, иначе 0.6 мм. Снимок другого разрешения (поперечный пиксель вне 0.54–0.70 мм
  или продольный вне 0.4–1.0 мм) пересчитывается к пикселю 0.6 мм перед измерениями: фильтры детекторов настроены на разрешение
  аппарата организатора. Копии тестовых снимков ×3 и ×0.5 дают те же вердикты, что оригиналы.
* Посторонние предметы на кости ищутся по зонам со своими порогами (поверх таза и поверх позвоночника).
  Реальных примеров предметов на кости в наборе нет; по стенду из настоящих предметов, перенесённых
  на нормальные снимки (`validate_foreign_object.py`), поверх таза находится ~96%, поверх позвоночника
  лишь ~16% — тонкий металл на фоне позвонков похож на замыкательные пластинки.
* Верхняя граница позвоночника (половина Th12) не проверяется: в разметке один такой пример.
* Сервис — помощник контроля качества, не средство диагностики.

  roi.py             ориентиры бедра и область интереса
  rotation.py        ротация бедра: малый вертел, офсет головки
  features.py        все измерения одного снимка
  model.py           решение по критериям (пороги, калибровка), обучаемые параметры, режимы
  settings.py        настройки контроля: режим, пороги, критерии, проверка ввода
  region.py          область по анатомии для снимков нестандартного размера
  pipeline.py        пакетная обработка (два прохода, остановка), область и сторона, устойчивость к ошибкам

  predict.py         командная строка
  api.py, static/    HTTP API и веб-интерфейс (журнал, «Метрики», «Разметка врача»)
  review.py          инструмент врача: разметка, дообучение, модель-кандидат, применение и откат
  feedback.py        хранение разметки врача и подмешивание её в обучение (--feedback)
  cv.py              честная кросс-валидация (группы по исследованию, бутстрэп ДИ)
train.py             обучение итоговой модели → models/quality_model.joblib
evaluate_final.py    честная оценка системы тем же кодом → out/metrics_final.json

make_metrics_table.py таблица метрик с 95% ДИ для презентации → out/metrics_table.md
tests/               тесты: дымовой прогон, настройки, загрузка файлов (python -m pytest tests -q)

experiments/         исследования, не вошедшие в сервис (SigLIP, CLIP, SAM, VLM, перестановочный тест),
                     — откуда цифры раздела «Что пробовали» в REPORT.md; см. experiments/README.md

## Системные требования

| | Минимум | Рекомендуется |
|---|---|---|
| CPU | 2 ядра x86-64 | 4+ ядер |
| ОЗУ | 2 ГБ | 4 ГБ |
| GPU | не нужен | не нужен |
| Диск | 2 ГБ (образ ~750 МБ) | 5 ГБ |

Скорость на CPU (ноутбук): 0.03–0.15 с на снимок, весь обучающий набор (499 файлов, 100 исследований)
за 21 с, загрузка модели ~2 с — с большим запасом до лимита ТЗ в 3 минуты на исследование.
Нейросетей в итоговой системе нет: только измерения и обученные пороги.

Зависимости и версии — `requirements.txt` (все зафиксированы), базовый образ
`python:3.10.16-slim-bookworm`.

## Сборка и запуск (Linux / UNIX)

Модель должна лежать в `models/` (в комплекте). Если её нет:

```bash
python train.py --data /path/to/НД_для_обучения # несколько минут на CPU
```

Далее:

```bash
chmod +x run.sh
./run.sh build
./run.sh predict /path/to/dicom_or.zip ./result  # пакетная обработка
./run.sh api                                     # веб-интерфейс: http://localhost:8000
./run.sh predict /path/in ./result my.json       # то же с настройками (см. «Настройки»)
PORT=8080 ./run.sh api my.json                   # другой порт и настройки сервиса
TRAIN_DATA=/path/to/НД_для_обучения ./run.sh api  # с дообучением в инструменте врача
./run.sh check /path/to/НД_для_обучения [/path/to/Для_теста]   # проверка решения с нуля → verification/
```

На Windows (Docker Desktop не нужен): Docker Engine в WSL2 Ubuntu —
`sudo apt-get install -y docker.io docker-buildx`, затем те же команды `run.sh` из WSL.
Пути к входу/выходу берите без кириллицы (например `/mnt/c/dxa_in`, `/mnt/c/dxa_out`).
Если за VPN в WSL нет сети — `networkingMode=mirrored` в `%USERPROFILE%\.wslconfig` и `wsl --shutdown`.

Без контейнера (Python 3.10):

```bash
pip install -r requirements.txt
python -m dxa.predict --input /data/in --output out/results.xlsx --series out/series [--config my.json] [--mode sensitive]
uvicorn dxa.api:app --port 8000
```

## Руководство пользователя (веб-интерфейс)

1. Запустить `./run.sh api` и открыть http://localhost:8000.
2. «Выбрать файлы» — zip-архив или несколько DICOM-файлов, либо «Папка...» — каталог целиком;
   «▶ Обработать».
3. В журнале строки красные — есть нарушение, зелёные — качественное, жёлтые — ошибка чтения.
   «только с нарушениями» — фильтр.
4. Щелчок по строке — снимок с разметкой (красное — нарушение) и заключение с числами и порогами;
   щелчок по снимку, кнопка «🔍 Просмотр» или двойной щелчок по строке открывают его в полном размере.
   На снимке бедра жёлтая линия — анализируемый медиальный контур (оценка ротации); галочка
   «наибольший выступ контура» над снимком отмечает его вершину. Если рамка области интереса
   не построена (короткий скан), причина написана в легенде. У снимка позвоночника, где найдены
   посторонние предметы, галочка «посторонние предметы» обводит их рамками (самые сильные отклики
   детектора, не больше четырёх) — видно, на что среагировал сервис, и ложную тревогу легко отбросить.
   Одинаковые по пикселям копии снимка в исследовании показывают тот же результат и ту же картинку
   (в таблице — колонка `duplicate_of`).
5. «Отчёт XLSX / CSV», «Доп. серии (ZIP)» — выгрузка результатов. Ссылка вида `/?job=<id>`
   открывает уже обработанное задание (и после перезапуска сервиса).
6. «■ Остановить» — прервать загрузку (виден процент) или остановить обработку: текущее исследование
   дорабатывается, отчёт по уже обработанным сохраняется (статус «Остановлено»).
7. «✎ Разметка врача» (для выбранной строки) — отдельный инструмент: подтвердить или исправить
   заключение по каждому критерию, обвести пропущенный посторонний предмет (найденные сервисом показываются пунктиром и учитываются сами — ложную рамку убирают щелчком; «чистый снимок» — без легенды и линий разметки); исходный DICOM и метки
   уходят в набор дообучения. Там же — «Дообучить и пересчитать метрики»: новая модель обучается на наборе
   организатора и разметке врачей, для неё считаются те же честные метрики; сравнение с действующей,
   «Применить» (прежняя версия сохраняется) и «Откатить».
8. «Метрики» — честные метрики в таблицах с 95% ДИ, режимы, поверка измерителя, стенд предметов.
9. «⚙ Настройки...» — режим чувствительности (с честными цифрами: какую долю брака находит
   и какую долю нормы верно оставляет), пороги, проверяемые критерии. Изменённые поля
   подсвечены, в строке состояния — «Настройки: изменено N»; «По умолчанию (ТЗ)» — сброс.
   Выбор запоминается в браузере и применяется к следующей обработке.

## Руководство по развёртыванию

* Сервер Linux с Docker. Каталог `models/` входит в комплект; сеть при работе не нужна.
* `./run.sh build` → `./run.sh api` (порт 8000) либо `./run.sh predict <вход> <выход>`
  для пакетной обработки закрытого набора без интерфейса.
* Задания API хранятся в `/data/jobs` контейнера (переменная `DXA_JOBS`); чтобы сохранять
  их между перезапусками, смонтируйте том: `docker run -v /srv/dxa-jobs:/data/jobs ...`.
* Проверка готовности — `GET /health` (используется HEALTHCHECK образа).
* Настройки сервиса по умолчанию — файл JSON (`./run.sh api my.json` или переменная `DXA_CONFIG`);
  каждое задание API может их переопределить.
* Инструмент врача: разметка хранится в `DXA_FEEDBACK` (`run.sh` — том `dxa-feedback`); дообучению нужен
  набор организатора (`DXA_TRAIN_DATA`, `TRAIN_DATA=... ./run.sh api`). Кандидаты и прежние версии модели —
  в `models/candidates`, `models/history`; чтобы принятая модель пережила пересоздание контейнера,
  смонтируйте том на `/app/models`.
* `/api/jobs/path` обрабатывает только каталоги из `DXA_INPUT_ROOTS` (в образе — `/data`), чтобы
  через API нельзя было прочитать произвольный каталог сервера.

## API

| Метод | Путь | Что делает |
|---|---|---|
| GET | `/` | веб-интерфейс |
| GET | `/health` | `{"status":"ok"}` — готовность |
| GET | `/api/settings` | настройки по умолчанию, пределы, честные метрики режимов |
| POST | `/api/jobs` | form-data `files`: zip и/или DICOM-файлы (имена с подкаталогами сохраняются), необязательно `settings` — JSON → `{"id", "status"}` |
| POST | `/api/jobs/path` | JSON `{"path": "/data/input", "settings": {...}}` — обработать каталог на сервере |
| GET | `/api/jobs/{id}` | статус (`running/done/error`), прогресс, строки результата, настройки задания |
| GET | `/api/jobs/{id}/results.xlsx`, `results.csv`, `series.zip`, `settings.json` | файлы результата |
| GET | `/api/jobs/{id}/overlay/{path}` | PNG с разметкой |
| POST | `/api/jobs/{id}/cancel` | остановить обработку; обработанное сохраняется, статус `cancelled` |
| GET | `/metrics`, `/api/metrics` | страница и данные метрик (CV с 95% ДИ, режимы, поверка, стенд) |
| GET | `/review` | инструмент врача |
| POST/GET/DELETE | `/api/feedback`, `/api/feedback/{id}` | разметка врача: `{job, row, labels, boxes, overlay_size, note}` |
| POST/GET | `/api/retrain`, `/api/retrain/cancel` | дообучение (фон), статус и сравнение метрик |
| GET/POST | `/api/models`, `/api/models/accept`, `/api/models/rollback` | версии модели, применение кандидата, откат |

Пример пакетной обработки через API:

```bash
curl -F files=@study.zip http://localhost:8000/api/jobs          # → {"id":"a1b2..."}
curl http://localhost:8000/api/jobs/a1b2...                       # статус и строки
curl -o results.xlsx http://localhost:8000/api/jobs/a1b2.../results.xlsx
curl -F files=@study.zip -F 'settings={"mode":"sensitive"}' http://localhost:8000/api/jobs   # с настройками
```

Ошибка в настройках — ответ 422 с понятным текстом (например, «axis_limit_deg: число от 0.5 до 30»).

## Входные данные

DICOM-файлы (любые имена и вложенность, zip допускается, в т. ч. вложенный; имена в zip из
Windows в cp866 распознаются). Исследование определяется по `StudyInstanceUID`, изображения —
по `SOPInstanceUID`. Одинаковые по пикселям копии обрабатываются один раз (`duplicate_of`).
Область (позвоночник/бедро) — по тегам и имени файла; при их отсутствии у снимков «родного»
размера аппарата организатора (ширина 240–320 пикселей) — по ширине (позвоночник 300, бедро 248–280,
порог 290; 252 из 252), у снимков любого другого размера — по анатомии (`dxa/region.py`: симметрия
и положение яркого столба, не зависит от масштаба; 248 из 252 на кросс-валидации, увеличенные
×3 и уменьшенные ×0.5 копии без подсказок — 6 из 6). Как определена область — в DICOM SR.
Наши же доп. серии (DICOM SC с разметкой из `series.zip`), загруженные обратно, не анализируются:
`Failure` с причиной «это доп. серия DXA-QC, а не исходный снимок».
Сторона бедра — по тегам/имени (`ЛПОБ`, `ППОБ`, `left`, `right`),
иначе по анатомии (головка и таз медиально).

## Выходные данные

`results.xlsx` и `results.csv` (UTF-8 с BOM), одна строка на файл изображения:

| Колонка | Описание |
|---|---|
| `path_to_study` | путь к файлу |
| `study_uid`, `image_uid` | из DICOM-тегов |
| `anatomical_region` | «Поясничный отдел позвоночника» / «Проксимальный отдел бедра» — без стороны («Разъяснения V2», вопрос 15) |
| `quality_class` | 0 — качественное, 1 — есть нарушение |
| `quality_prob` | вероятность нарушения, [0;1] («Разъяснения V2», вопрос 8): P(хотя бы одно нарушение) по откалиброванным вероятностям критериев. Порог `quality_class` подобран по F1, поэтому класс 1 возможен и при вероятности < 0.5 — для редкого брака оптимальный порог ниже 0.5 |
| `violation_type` | перечень нарушений через «;» без пробела («Разъяснения V2», вопрос 6; названия как в разметке организатора), пусто — нарушений нет |
| `processing_status` | Success / Failure |
| `time_of_processing` | секунды на изображение |
| `details` | объяснение по каждому критерию: измеренное значение и порог |
| `duplicate_of` | если файл — копия другого изображения исследования |
| `error` | текст ошибки при Failure |
| `settings` | пусто при настройках по умолчанию; иначе — что изменено («режим: высокая чувствительность; Допустимый наклон оси: 6° (по умолчанию 5)») |

С какими настройками получен результат, записано также на листе `settings` в `results.xlsx`
и в `settings.json` рядом с таблицей; в заключении каждый изменённый порог помечен
«[изменено пользователем; ТЗ: 5]», в DICOM SR — отдельный пункт «Настройки».

`series.zip` (или каталог `series/`): для каждого снимка `*.png`, `*_SC.dcm` (Secondary Capture
с разметкой, новая серия в том же исследовании), `*_SR.dcm` (Basic Text SR с заключением).

## Настройки

Всё, что можно настроить без переобучения. По умолчанию — как в ТЗ и как при оценке метрик.

| Параметр | По умолчанию | Что задаёт |
|---|---|---|
| `mode` | `balanced` | режим обучаемых порогов (посторонние предметы, ротация бедра): `sensitive` / `balanced` / `specific` |
| `axis_limit_deg` | 5 (ТЗ) | допустимый наклон оси позвоночника, ° |
| `roi_bottom_cm` | 3 (ТЗ) | отступ ниже малого вертела, см |
| `field_min_cm` | 13 | минимальная длина скана бедра (7 см области интереса + 3 + 3) |
| `iliac_min_frac` | 0.005 | «гребни подвздошных костей видны» — доля кости у нижнего края |
| `ischium_min_frac` | 0.02 | «седалищная кость в кадре» — доля кости в её зоне |
| `spine_min_width_px` | 290 | правило области без тегов: снимок шире — позвоночник (настроено под аппарат организатора) |
| `pixel_spacing_mm` | `null` | принудительный размер пикселя `[x, y]` в мм вместо тега (другой аппарат, неверный тег) |
| `criteria` | все `true` | отключение критериев: `spine_axis`, `spine_positioning`, `spine_foreign`, `femur_positioning`, `femur_roi` |

Режимы (честная кросс-валидация по пациентам, `out/metrics_final.json` → `режимы`):

| Режим | Порог обучаемых критериев | «Есть нарушение»: находит брака | верно оставляет нормы | F1 |
|---|---|---|---|---|
| `sensitive` | найти ≥ 90% нарушений обучения | 85% | 72% | 0.67 |
| `balanced` | максимум F1 (по умолчанию) | 84% | 85% | 0.76 |
| `specific` | ≤ 5% ложных тревог на обучении | 59% | 91% | 0.66 |

Режим меняет только обучаемые пороги, поэтому общая чувствительность в `sensitive` растёт мало:
пропуски в основном у оси позвоночника, где порог задан ТЗ (5°). Его можно снизить отдельно
(`axis_limit_deg`), но тогда проверка уже не «по ТЗ» — это помечается в заключении.
`quality_prob` от настроек не зависит (вероятности откалиброваны по разметке), поэтому
ROC-AUC от режима не меняется. Пример файла — `config.example.json`.

## Модель, предобработка, постобработка

* **Предобработка:** чтение `pixel_array` (JPEG/JPEG2000 через pylibjpeg), MONOCHROME1 → 2,
  нормализация по перцентилям 0.5–99.5; размер пикселя — из Exposed Area с проверкой
  правдоподобия; сторона бедра учитывается при поиске ориентиров.
* **Измерения** (без обучения): средняя линия позвоночника и угол по двум крайним участкам;
  доля кости гребней у нижнего края; гессиановый детектор тонких ярких линий; маска бедра,
  головка (карта расстояний), малый вертел (выступ медиального контура), офсет головки,
  область интереса и отступы в см.
* **Обучаемое:** медиана выступа малого вертела у нормы, эталонные распределения оценок ротации,
  пороги детектора предметов и оценки ротации (максимум F1 на обучающих данных), изотоническая
  калибровка оценок в вероятности для `quality_prob` (по out-of-fold оценкам, фолды по исследованиям).
* **Постобработка:** флаг по каждому критерию, `quality_class` = ИЛИ флагов области;
  несколько нарушений перечисляются все (мультилейбл).

Обучение — `train.py`; честная оценка — `evaluate_final.py` (вложенная CV, группы по исследованию,
5×5 фолдов, 95% ДИ бутстрэпом по исследованиям). Дообучение на новых данных: положить набор
в формате организатора и выполнить `train.py --data ...`, затем пересобрать образ.

## Известные ошибки и обработка

| Ситуация | Что происходит |
|---|---|
| файл не DICOM / битый | строка с `Failure`, текст в `error`, пакет продолжается |
| DICOM без пикселей (SR, DICOMDIR) | пропускается |
| сжатие, которое не декодируется | `Failure` с сообщением pydicom |
| Exposed Area отсутствует или неверен | размер пикселя 0.6 мм, измерения в мм приблизительны |
| бедро почти не попало в кадр | ориентиры ненадёжны; оценки ротации/области интереса могут быть неверны |
| область не определилась по тегам | снимок «родного» размера — по ширине (`spine_min_width_px`), иначе по анатомии |
| на вход подали `series.zip` (наши PNG / DICOM SC / SR) | PNG и SC — `Failure` с причиной, SR пропускается; загружать нужно исходные DICOM |
| снимок другого разрешения (поперечный пиксель вне 0.54–0.70 мм, продольный вне 0.4–1.0 мм) | пересчитывается к 0.6 мм, вердикты как на исходном разрешении; если тег размера неверен — задайте `pixel_spacing_mm` |
| неверные настройки | CLI: сообщение и код 2; API: 422 с текстом; задание не запускается |
| одноимённые файлы в разных папках (IM0001...) | сохраняются раздельно, ничего не затирается |
| пустой (однородный) или крошечный снимок; анатомия не найдена | `Failure` с причиной — а не вердикт «норма» по ненайденным измерениям |
| отдельная величина не измерена (например, контур малого вертела) | в заключении «не измерено», решение по остальным измерениям |
| очень большой вход (сотни тысяч файлов) | чтение в два прохода: в памяти только текущее исследование; обработку можно остановить |
| очень длинный путь к каталогу вывода на Windows (> 260 символов) | доп. серия не записывается, текст ошибки в `error`; результат по снимку есть |
